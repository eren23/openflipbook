change, merge or deployment is authorized by this document.

This is the current priority order for place consistency, transitions and demos.
Earlier plans and experiment reports remain historical evidence, not competing

## Product Direction

Keep the illustrated map as the main experience. Enter the intended place,
preserve recognizable architecture and art style, and return to the same saved
world. AI-generated motion should add something visibly worthwhile without
concealing an incorrect destination.

Three independently testable requirements:

1. Identity: this is the selected building/place, not a similar substitute.
2. Movement: direction, viewpoint and visible landmark motion make sense.
3. Persistence: revisits retain saved images/assets without regeneration.

Passing any one does not imply the other two. A good demonstration is a result
of meeting these requirements, not a substitute for them.

automatic creation remain unimplemented. Do not replace the illustrated map,

### P0. Establish One Valid Task, Without Spending

Status: next. Output: a reviewed input package and exact experiment manifest.

  routing fix, completed experiment tooling and unfinished geometry prototype.
  Do not merge them as one unreviewed batch or discard existing work.
- Reinspect the saved quay, shop and doorway images in the actual app. Record

  view is compatible. Otherwise stop at the doorway; do not force the narrative.

Exit gate: the user accepts the selected place, arrival and guide direction.
If references conflict, repair the input package first. A source image cannot
prove unseen interior geometry; any authored interpretation must be labeled.

### P1. Compare AI Movement, Not Model Marketing

Status: queued behind P0 and explicit batch approval.
Output: synchronized comparison viewer, raw clips, failures and receipts.

- First comparison: Ray 3.2 versus Seedance 2.5 on the same P0 scene and movement.
  Two independent submissions per model, one declared configuration each. Set
  distinct seeds only where the endpoint exposes them; otherwise record that
  randomness is provider-managed. Do not invent unsupported seed parameters.
- Supply compatible appearance references and the same motion guide where the
  endpoint permits. Record differences in conditioning, dimensions, duration,
  audio behavior and effective prompts instead of calling them identical tests.
- Reuse the existing bench/viewer patterns. Implement only the endpoint-specific
  adapters and manifest fields needed for this comparison, not a general engine.
- Keep a deterministic source-pixel/cut baseline and the guide visible. Existing
  H3/LTX clips with different endpoints are historical examples, not scored peers.
- Inspect beginning, end, threshold/occlusion events and at least 11 evenly spaced
  frames; also watch native-speed playback. Show every attempt, not just a winner.
- Annotate observed output landmarks separately from expected guide positions.
  For visible landmarks with correspondence, report normalized center error at
  each sample. Proposed pilot tolerance: <=3% of image diagonal. This is a
  chosen screening threshold, not an established perceptual calibration.
- Do not score truly occluded landmarks as visible. Unexpected disappearance,
  duplicated architecture, wrong turns, wrong arrival, dissolves masquerading as
  motion, and material style changes are explicit failures. Missing observations
  remain unverified, not automatic passes.
- Human playback verdict is required: does this feel like moving toward the
  correct place, and does it improve on the baseline? A VLM score cannot override
  a visible identity or continuity failure.

Budget proposal: $10 for four short clips, with current estimate in the report.
No extra stills, judges or rerolls are included. Reserve before submission and
stop if live pricing or required inputs exceed the authorized batch.

Exit gate: select a candidate only if both runs avoid the categorical failures
and meet the recorded screening checks, with a positive human verdict. Two runs
are a pilot signal, not proof of general reliability. Otherwise publish the
failure diagnosis and stop; do not make a flattering film from a failed trial.

### P2. Test Persistent Generated Space Separately

Status: follows the persistent local-place input/fidelity gate above; it no
longer depends on finishing P1's video comparison. Paid generation still requires
separate approval and verified inputs.
Output: one inspectable Marble environment and an asset/identity audit.

- Verify World API access and download/use terms. A new account or top-up needs
  explicit approval; do not enable auto-refill.
- Generate from one accepted ground-level illustrated place. Start with one
  world; a second requires a specific hypothesis about the first one's failure.
- Retain asset hashes, model/version, source references, world ID and the
  relationship to the canonical place. Render the saved splats with an existing
  maintained viewer/library; do not author a custom splat renderer.
- Inspect the known facade, palette and landmarks against the source. Inspect
  newly exposed surfaces for holes, distorted architecture and inaccessible areas.
- Capture a sideways move, turn, short forward move and return from the same
  asset. Reload and repeat without generation. Distinguish deterministic asset
  reuse from browser-dependent rendered pixels.
- Check desktop/mobile framing, performance, load failures and resource cleanup.
  An isolated test view is enough; no main-navigation integration yet.

Budget proposal: separate $3 generation reservation for up to two standard
worlds. A required minimum $5 credit purchase is a distinct approval decision.

Exit gate: recognizable illustrated place, useful navigable area, tolerable
disocclusion artifacts and stable asset reuse. This establishes only that local
place. It does not prove a complete city or a connected exterior/interior world.

### P3. Fix Automatic Arrivals and Integrate Only What Earned It

Status: blocked on the evidence above, not on a calendar date.
Output: reviewed opt-in implementation plus fresh-arrival evaluation.

- Evaluate automatic landmark-local/canonical references on at least three
  different worlds, including a facade, tower and interior threshold. Use fresh
  attempts with frozen prompts and record rejected/unpublished candidates.
- Report correct-place rate, camera/framing errors, duplication, style retention,
  cost and end-to-end latency. Curated still selection is not this benchmark.
- For a selected video route, freeze provider arguments and source/destination
  image hashes in its cache identity. Persist only accepted clips per edge.
  Model/config changes must not silently reuse incompatible clips.
- Do not require video completion to enter a saved destination. Failure or delay
  retains the existing decode-first source-pixel/cut behavior. No surprise billing
  on hover, navigation, reload or replay.
- Keep any approved generated environment linked to canonical place identity;
  a new viewpoint must not silently create another unrelated place. Geometry
  integration is conditional on P2, not mandatory for video integration.
- Cover cancelled/stale requests, invalid references, decode/provider failures,
  authorization, persistence, return, reload and zero-submission replay.
- Run targeted tests during each scoped change and applicable full suites before
  merge. Review and merge one coherent PR at a time, then smoke-test the combined
  local state before proceeding. Deployment and flag graduation are separate.

Exit gate: cross-world evidence, passing regression/browser checks, explicit
review, and an opt-in user playback check. No global auto-generation default yet.
